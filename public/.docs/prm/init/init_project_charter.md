## 1. Business Case

Toy project: a Balatro-style roguelike where pure coin tosses replace cards entirely. Goal: a complete, polished 1-hour gameplay experience as a solo, zero-budget web project — proving the full loop (design → build → balance → ship) and producing a shareable, replayable game.

Core identity: every hand is generated by flipping 5 coins; scoring comes from the patterns of heads and tails — a 50/50 gamble at the heart of every decision.

## 2. Project Objectives & Success Criteria

1. Complete 1-hour run — full 12-blind run playable start to finish (target 45–60 min)
2. Core loop fun and clear — pattern-based scoring (5-coin hands) + coin charms work as designed (playtest pass)
3. Reproducible, shareable runs — same seed produces identical run, seeded RNG (verified by tests)
4. Persistence — save/resume via localStorage works across sessions (verified manually)
5. Core logic tested — vitest suite covering scoring + RNG, 100% pass
6. Ship on schedule — vertical slice in week 1 (M2, 2026-09-22); full run by M4 (2026-10-03)

## 3. High-Level Scope

In scope:
- Core loop: 5-phase hand flow — draw 8 coins (hand size, upgradable in the shop) from the coin deck, pick up to 5 to play, the game tosses them, buffs (charms) are applied, then score by pattern (5 same = "Jackpot", 4 same, 3 same, …); unlimited discard (draw-enchant coins redraw)
- Coin deck (Balatro-style): a persistent collection of ceramic coins (base 80, re-tuned 2026-09-14 + purchased special coins) the hand is drawn from; reshuffled each blind, finite within a blind (hand shrinks on deck-out, empty slots count as nothing); individual coins carry permanent effects (v1 core set of 9)
- Run structure: 4 rounds × 3 blinds = 12 blinds (~1 hour per run)
- Charms: collectible modifiers (chips/mult boosters, extra hand, payday, jackpot fever) that alter scoring; left-to-right order matters, reorderable via drag
- Shop: buy charms / special coins / reroll between blinds with earned currency; merge (sacrifice a coin into another) and remove (delete a coin) actions
- Seeded runs: reproducible runs with shareable seeds (pure-rand)
- Save/resume: persist to localStorage (zustand + persist)
- UI: minimal flat art style — Tailwind + shadcn/ui (copy-in components, no CSS bloat)
- Juice: coin-flip animation, chips×mult ticker, confetti on blind clear, SFX (flip, win/lose stingers) — no music
- Tests: vitest for scoring and RNG core logic

Out of scope:
- Cards, poker hands (pokersolver explicitly NOT used) — the piggy ceramic coin-deck is the in-scope deck mechanic
- Multiplayer or online play
- Public hosting / Steam release (local-only delivery)
- Music track
- Mobile-native builds (browser window only)
- Localization, achievements, leaderboards

## 4. High-Level Requirements

- Runs entirely in the browser via `npm run dev` / `npm run build` (local only)
- Vite + React + TypeScript scaffold (`npm create vite@latest`) at repo root — absorbs the current Node package.json
- State: zustand + immer + persist middleware
- Seeded RNG: pure-rand (reproducible runs, shareable seeds)
- UI: Tailwind + shadcn/ui; animations via @formkit/auto-animate
- Drag-to-reorder charms: @dnd-kit/sortable
- Juice: canvas-confetti, howler (SFX), react-countup / motion animated values
- Tests: vitest (free with Vite)
- Zero-cost budget: all libraries free/open-source, no paid assets

## 5. High-Level Risks

1. Scope creep — Balatro is huge; a toy project must stay at 12 blinds (Schedule, impact High / likelihood High) — enforce the out-of-scope list; cut features, not the 1h target
2. Solo-dev bandwidth / burnout (Resource, High / Medium) — slice-first timeline (playable week 1), fixed 3-week box
3. Balance — 1-hour pacing unproven for coin-toss scoring (Technical, Medium / High) — seeded runs make balance A/B testing cheap; playtest every blind
4. Seeded RNG correctness — reproducibility broken (Technical, Medium / Low) — vitest coverage of RNG + scoring before building UI on top
5. Charm left-to-right scoring-order complexity (Technical, Low / Medium) — pure scoring function, unit-tested; dnd-kit for the UI layer only
