# M13b — Animation System Migration to Motion (Framer Motion)

**Depends:** M13 (Juice — the animations exist and are green), M13a (interaction overhaul — drag/drop, projected score, auto-advance) · **Files:** `src/lib/motion.ts`, `src/components/hand/{hand-coin,toss-coin,play-slot,score-ticker}.tsx`, `src/components/hand/toss.ts`, `src/components/juice/{choreography.ts,use-scoring-choreography.ts,scoring-choreography.tsx,screen-shake.ts,screen-shake.tsx,particles.ts,particles.tsx}`, `src/components/run/{discard-ghost.tsx,deal.ts}`, `src/components/ui/button/{buttonPhysics.tsx,buttonVariants.tsx}`, `src/pages/run.tsx`, and the CSS carrying animation (`src/components/hand/{coin.css,toss-coin.css}`, `src/components/juice/choreo.css`, `src/components/run/run.css`, `src/index.css`) · **Source of truth:** [SDD UX](../../sdd/software_design_ux.md) §0 (juice boundary), §2 (motion tokens), §4–§5 (timing table), §6 (scoring choreography), §7 (particles & shake), §8 (reduced motion), §9 (perf); [Component Design](../../sdd/software_design_component.md) C10; the [M13 Juice plan](plan_wbs-m13-juice.md). Conventions: [overview](plan_wbs-overview.md).

*Goal: consolidate the animation layer onto a single library — **Motion** (the current name of Framer Motion) — so the library owns timing, sequencing and springs instead of the hand-rolled `setTimeout` chains, module-level `requestAnimationFrame` loops, CSS `@keyframes`, and direct `style.transform` writes that grew up alongside M13. Today the system is a **mix**: `hand-coin`, `play-slot`, `toss-coin`, `score-ticker`, `scoring-choreography` and `discard-ghost` already use `motion`/`useAnimation`/`animate`/motion values, while the choreography beats, screen shake, coin micro-motions, and the run-screen timing glue are still bespoke. This milestone finishes the job: one motion model, one set of tokens, timing that can't drift from the animation that produces it.*

**Boundary (UX §0 — unchanged):** the migration is **presentation-only and behavior-preserving**. Juice reads `lastScore`/`RunState`, never mutates state, never gates an action, and stays **skippable** (a skip snaps to the settled end and changes no number — 13.4). The 3D coin still always lands on the engine's `Slot.face`. This is a **refactor**: the same beats, the same durations (the `lib/motion.ts` tokens and `beatDurations` math are the source of truth — port them, don't retune), the same landing faces, and the same public component props where practical. No `src/core/` or `src/state/` file is touched; the engine and store test suites stay 100% green and are not edited. `Math.random()` stays banned in `core`/`state` — the presentational randomness in shake/particles is unaffected. Retuning of curves, if any is wanted, is a **separate** follow-up (M13c), not this migration.

## Current state (audit — what is and isn't on Motion)

**Already on Motion (leave the behavior, modernize the API where noted):**
- `hand-coin.tsx` — `motion.button` with shared `layoutId`/`layout` pick↔unpick, the deal-flight via `initial`/`animate`, `useReducedMotion`. *But* the hover tilt is written straight to the DOM (`style.transform` on every `pointermove`) and the 6th-pick shake is a **CSS `@keyframes coin-shake`** restarted by a `key` remount.
- `play-slot.tsx` — `motion.button` + shared `layoutId`.
- `toss-coin.tsx` — uses the **legacy `useAnimation()` controls** driven by an `async` chain with a `sleep()` (`setTimeout`) stagger.
- `score-ticker.tsx` — idiomatic `animate()` + `useMotionValue` + `useTransform` count-ups.
- `scoring-choreography.tsx` — per-element `motion.span` animations gated on the current beat.
- `discard-ghost.tsx` — `motion.div` flight with `onAnimationComplete`.

**Still bespoke (the migration targets):**
- `use-scoring-choreography.ts` — the 7-beat sequence is a **manual `setTimeout` chain** (`scheduleBeats`); the visual pieces are Motion but the *timeline* is hand-rolled.
- `screen-shake.ts` — a **module-level singleton + `requestAnimationFrame` loop** writing `style.transform`, with `attachShakeEl` DOM plumbing.
- CSS `@keyframes` — `coin-shake` (`coin.css`), `onboarding-in` (`run.css`).
- `hand-coin.tsx` pointer tilt — direct `style.transform` writes.
- `buttonPhysics.tsx` — Tailwind CSS transitions (`transition-[...]`, `hover:`/`active:`).
- `run.tsx` timing glue — `useTossSfx`, the `useAutoScore` delay math, and `useTossProjection` landing timers all re-derive `TOSS.stagger`/`TOSS.rise` in `setTimeout`, in parallel with the toss animation they must stay in step with.
- `particles.ts` — a **custom canvas particle/confetti engine** with its own rAF loop. **Deliberately kept** (see 13b.9): Motion is not a particle engine.

### Timeline consolidation

- [ ] **13b.3 Toss: legacy `useAnimation` + `sleep()` → a Motion timeline.** Replace `toss-coin.tsx`'s imperative `controls` + `async`/`sleep` stagger with `useAnimate` + an `AnimationSequence` (or keyframes with a `times` array): the rise (ease-out) → spring-bouncy settle, the parallel tumble timed to the first landing, and the left→right stagger all expressed declaratively; the landing sparkle (`emitBurst`) and land `sfx` fire from the sequence's `at`/completion markers, not a `setTimeout`. Keep the reduced-motion 2D cross-fade path. The face is still store-resolved (UX §0). *Accept:* no `setTimeout`/`sleep` in `toss-coin.tsx`; the coin still lands on `Slot.face` at the same total time (`TOSS.rise + TOSS.tumble` + stagger); `toss-coin.test.tsx` green (reduced-motion still cross-fades, same face).

- [ ] **13b.4 Scoring choreography: `setTimeout` beat scheduler → a Motion timeline.** Replace `scheduleBeats`/`useScoringChoreography`'s `setTimeout` chain with a Motion-driven sequence (`useAnimate` `AnimationSequence`, or a variant tree with `delayChildren`/`staggerChildren`/`when`) whose segment lengths come from the **unchanged** pure `beatDurations()` math. The seven beats (reveal → banner → chips → mult → resolve → cash → settle) advance on the sequence, and the per-beat effects (bursts, shake trigger, sfx ticks) hang off sequence markers rather than the nested `window.setTimeout` timers in `scoring-choreography.tsx`. **Skip (13.4)** completes/stops the sequence and snaps to the settled end. *Accept:* no `setTimeout` drives beat advancement or the beat-effect ticks; a tap/key still snaps to beat 7 changing no number; `choreography.test.ts` (the pure math) untouched and green; the choreography still reads as escalating.

- [ ] **13b.5 Screen shake: module rAF singleton → Motion.** Replace `screen-shake.ts`'s global `requestAnimationFrame` loop + `attachShakeEl` with a Motion animation on the `ScreenShake` wrapper — an `x`/`y` keyframe burst with exponential-decay easing (amplitude from `SHAKE_AMPLITUDE`, ~300ms), driven by a motion value or `useAnimate`. **Zero under reduced motion** (the trigger is a no-op). The loop must run only while a shake is active (no idle rAF — UX §9). *Accept:* no standalone rAF loop or module-level DOM handle for shake; amplitude still scales by tier and clear (`CLEAR_SHAKE_AMPLITUDE`); `screen-shake.test.tsx` green; reduced-motion shake is exactly zero.

### Micro-motions & CSS

Tilt/lift/shake all stay gated under reduced motion and mid-drag. *Accept:* no per-`pointermove` DOM `transform` write and no `coin-shake` `@keyframes`; the `key`-remount hack is gone; `hand-coin.test.tsx` green; reduced motion drops lift/tilt/shake (badge brightening — a color change — stays).

- [ ] **13b.7 Retire the remaining CSS keyframes & Tailwind motion.** Migrate `onboarding-in` (`run.css`) to `AnimatePresence` + `motion` on the onboarding hint, and move the Ceramic-Tactile **button physics** (`buttonPhysics.tsx`'s Tailwind `transition-[…]`/`hover:`/`active:`) onto a `motion` button with `whileHover`/`whileTap` (or keep the pure-CSS press if it reads identically — record the decision here). After 13b.6–13b.7 the only `@keyframes` and the only rAF loop left in `src/` belong to the sanctioned canvas engine (13b.9). *Accept:* `grep -r "@keyframes" src` returns nothing outside a documented exception; onboarding enter/exit runs through `AnimatePresence`; `run.13a10.test.tsx`/`onboarding-hint.test.tsx` green; reduced-motion still disables the entrance.

- [ ] **13b.8 Fold the run-screen timing glue into the animation lifecycle.** `useTossSfx`, `useAutoScore`'s delay computation, and `useTossProjection`'s per-coin landing timers each re-derive `TOSS.stagger`/`TOSS.rise` in `setTimeout`, parallel to (and able to drift from) the toss animation. Drive them from the toss sequence instead: per-coin landing → the sequence's per-coin completion (feeding `setLanded` for the projected ticker, 13a.7), toss whoosh sfx → the same markers, and the auto-score trigger → the sequence's end (still an explicit Score fast-forward remains). *Accept:* the projected score, land sfx, and auto-advance are driven off the toss animation's own events, not independent timers; a re-flip still recomputes without a reset; `run.13a7.test.tsx` and `run.juice.test.tsx` green; auto-score still never fires while an Echo re-flip is available.

### Particles (scoped exception)

- [ ] **13b.9 Keep the canvas particle engine; wire its triggers to Motion.** Motion is a layout/gesture/timeline library, **not** a particle system — re-implementing 200–300 confetti pieces as `AnimatePresence` DOM nodes would regress the UX §9 perf budget. So `particles.ts`'s canvas + rAF engine **stays as the one sanctioned rAF loop**. What changes: its *triggers* (`emitBurst`, `emitConfetti`) fire from Motion sequence markers (13b.4) instead of standalone `setTimeout`s, and `attachLayer`/`disposeParticles` follow the component lifecycle (dispose on unmount, UX §9). Record this as a deliberate deviation here and in the M13 deviation note. *Accept:* the particle engine is the only rAF loop in `src/`, called out in this doc; bursts/confetti still fire on their beats; `particles.test.tsx` green; the layer disposes on unmount (no idle loop).
